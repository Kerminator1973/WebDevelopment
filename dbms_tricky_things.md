# Ловушки при использовании DBMS

Использование GUID в качестве IDENTITY записи позволяет упростить синхронизацию данных между несколькими экземплярами СУБД, но, в общем случае, GUID работает значительно медленнее, чем целочисленный IDENTITY. На миллионах записей это может приводить к ощутимым потерям времени при выполнении запросов.

Некоторые разработчики-практики часто сохраняют журнал аудита в отдельную таблицу в базе данных. Обоснование - не требуется дополнительных процессов и согласования для получения логов с сервера. Но этот механизм может вступать в конфликт с транзакционной моделью:

- открыли транзакцию
- возник сбой
- записали проблему в журнал аудита
- выполнили Rollback

Транзакция потеряна, концов по проблеме не найти.
