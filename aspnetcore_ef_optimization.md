# Оптимизации кода, работающего с базами данных

По умолчанию EF для каждой загруженной сущности:

- сохраняет её в локальном кэше контекста
- запоминает исходное состояние (snapshot значений)
- следит за изменениями свойств, чтобы при вызове SaveChanges() сформировать нужные UPDATE/DELETE/INSERT

Когда вы вызываете .AsNoTracking() на DbSet или на IQueryable, EF не добавляет эти сущности в трекинг-граф и не хранит их исходное состояние. В результате при изменении таких сущностей и вызове SaveChanges() EF не увидит никаких изменений и ничего не сохранит в БД.

Пример:

```csharp
// С трекингом (по умолчанию)
var item = context.Items.First(i => i.Id == 1);
item.Name = "Новое имя";
context.SaveChanges(); // EF сгенерирует UPDATE

// Без трекинга
var itemNoTrack = context.Items.AsNoTracking()
    .First(i => i.Id == 1);
itemNoTrack.Name = "Другое имя";
context.SaveChanges(); // Ничего не произойдёт: EF не отслеживает эту сущность
```

Основные выгоды:

- Производительность. Меньше аллокаций, меньше работы по сравнению значений и поддержанию графа. Особенно заметно на больших выборках
- Меньше памяти. Не хранится кэш отслеживаемых сущностей и их «старых» значений
- Упрощение логики. В read-only сценариях вы точно знаете, что случайное изменение объекта не приведёт к незаметному UPDATE
